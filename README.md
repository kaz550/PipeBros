# 土管兄弟

初代『マリオブラザーズ』の「足場を下から叩いて敵をひっくり返し、体当たりで倒す」遊びを題材にした、C++ / DxLibによる制作プロジェクトです。

> 現在は企画・設計段階です。このREADMEは初期案であり、「土管兄弟」固有のゲーム本体は未実装です。操作や数値、ファイル構成は制作に合わせて更新します。

## 開発ベース

[Game A Week for DxLib — Week05: Endless Jump Runner](https://github.com/kaz550/gaweek-week05-EndlessJumpRunner) をベースに制作します。

既存のプロジェクト構成を土台に、横スクロールのエンドレスランゲームから、固定画面のアクションゲームへ作り替えます。

### 既存処理の活用方針

ベースプロジェクトのREADMEに記載されている機能をもとに、次の処理の活用を予定しています。具体的な再利用範囲はソースコードを確認しながら決定します。

| 処理 | 土管兄弟での活用方針 |
| --- | --- |
| 入力管理 | 左右移動・ジャンプ・決定操作に対応させる |
| ジャンプ・重力・可変ジャンプ | 移動と足場判定を加え、操作感を調整する |
| deltaTimeベースの更新 | 移動・重力・状態の経過時間の管理に活用する |
| AABB衝突判定 | プレイヤーと敵の接触判定の土台として活用する |
| Title → Game → Result | クリア・ゲームオーバー・再プレイに対応させる |
| BGM / SE再生 | ジャンプ・突き上げ・撃破・ミスの音を追加する |
| 描画 | キャラクター・床・土管などを、用意したスプライト画像で描画する方式へ変更する |

無限スクロール、ランダム障害物生成、距離ベースの得点は、固定ステージ、敵の出現管理、敵の撃破による得点へ変更する方針です。

## アクションの実装方針

| 要素 | 今回の実装方針 |
| --- | --- |
| 移動・ジャンプ | 位置と速度を持ち、重力や入力によって更新する |
| 足場 | 横方向の範囲と上面・下面の高さをデータで管理する |
| 着地 | 落下中に足元が足場の上面を通過したかを調べる |
| 突き上げ | 上昇中に頭が足場の下面に到達したら、打撃位置を記録する |
| 敵の反応 | 打撃位置に近い足場上の敵の状態を切り替える |
| 足場の揺れ | 当たり判定とは分けて、描画時のずれとして表現する |
| 左右の移動 | 画面の端を越えたら反対側へ移す |

## ゲーム概要（初期案）

固定画面・1人プレイのアクションゲームを制作します。

1. 足場を移動する敵の位置を確認する。
2. 敵がいる足場を、下からジャンプして叩く。
3. ひっくり返った敵に体当たりして倒す。
4. 規定数の敵を倒すとステージクリアになる。

通常状態の敵に触れるとミスになります。ひっくり返った敵は一定時間で復帰する初期案とし、猶予時間は実際に遊んで調整します。

## 最初の完成目標

**固定画面1ステージで、移動・ジャンプ・足場への着地ができる状態**を最初の目標にします。

プレイヤーと床タイルのスプライトを用意し、画像を使った表示と移動から実装します。ゲーム内のキャラクターやステージには、DxLibのプリミティブ描画による代用を使用しません。

- [ ] ウィンドウを開き、背景・足場・プレイヤーを表示する。
- [ ] 左右に移動できる。
- [ ] 接地中にジャンプできる。
- [ ] 重力で落下し、床や足場に着地する。
- [ ] 足場の下からぶつかったとき、上昇が止まる。
- [ ] 画面の左右を移動でつなぐ。

## ゲームの完成条件

最初の完成目標を達成してから、敵とゲーム進行を追加します。

- [ ] 敵が出現し、足場上を移動する。
- [ ] 足場を下から叩くと、近くの敵がひっくり返る。
- [ ] ひっくり返った敵に触れると倒せる。
- [ ] 時間が経過すると、ひっくり返った敵が復帰する。
- [ ] 通常状態の敵に触れるとミスになり、残機が減る。
- [ ] 残機がある場合は再開し、なくなるとゲームオーバーになる。
- [ ] 得点と残機を表示する。
- [ ] 規定数の敵を倒すとクリアし、再プレイできる。

まず1人プレイと基本的な敵1種類でゲームの流れを完成させ、その後に下記の敵・ギミックを段階的に追加します。2P用の素材は準備しますが、2人プレイの操作・ルールと複数ステージの仕様は今後決定します。

## 操作案

| 操作 | キー |
| --- | --- |
| 左へ移動 | ← |
| 右へ移動 | → |
| ジャンプ | Space |
| 開始・結果画面から再プレイ | Enter |
| 終了 | Esc |

ジャンプはキーを押した瞬間に判定し、押し続けるだけで着地後に再ジャンプしない設計を初期案とします。

## 設計の方針

- 入力、ゲーム状態の更新、描画を分ける。
- プレイヤー・敵・足場のデータを整理し、役割が増えたら処理を分割する。
- 前回と今回の位置を使い、足場の面を通過したことを判定する。
- 敵をひっくり返す処理と、倒す処理を別の条件として扱う。
- 調整する値は名前を付け、意味が分かる場所にまとめる。
- デバッグ表示で当たり判定、速度、接地状態、敵の状態を確認できるようにする。

ベースプロジェクトの構成を活用し、固定画面アクションに必要なクラスや処理を追加・整理します。

### 素材の形式（案）

- 背景が不要な画像は透過PNGで用意する。
- アニメーションは、同じ大きさのセルを並べたスプライトシートを基本案とする。
- プレイヤーの各セルは足元の位置をそろえ、切り替え時の表示のずれを防ぐ。
- 描画サイズと当たり判定の大きさは別々に管理する。
- 各画像のサイズ、セル数、並び順、再生速度、左右反転の扱いは、素材制作前に決定する。

素材は準備予定であり、現時点で収録済みであることを示す一覧ではありません。
